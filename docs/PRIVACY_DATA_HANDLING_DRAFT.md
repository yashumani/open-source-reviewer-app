# ForkWise Privacy and Data-Handling Notice — Draft

> **Draft for product and legal review.** This document describes the intended beta behavior supported by the current implementation. It is not a final privacy policy, terms document, or legal approval.

## Scope

ForkWise reviews public GitHub repositories using static evidence. The browser preview and hosted runner have different data paths, which must remain visibly distinguished until hosted mode is activated.

## Browser-analysis mode

The current public reviewer calls GitHub directly from the user's browser. ForkWise's hosted database does not receive the repository URL, use-case context, findings, evidence, or exported report through that path. GitHub and the user's network/browser still process those requests under their own policies.

## Hosted-runner beta mode

When hosted mode is explicitly enabled, the service may process and temporarily store:

- the submitted public GitHub repository URL;
- normalized adoption context: intent, use-case text, deployment target, sensitivity classification, team size, and external-service policy;
- a client-generated idempotency identifier;
- job state, progress, timestamps, analyzer/schema version, and sanitized failure information;
- the exact analyzed commit SHA;
- a generated evidence-first report derived from public repository content;
- a one-way client/rate-limit hash rather than a raw client address where supported.

## Public repository content

The runner is designed to fetch only:

- public GitHub metadata;
- the default branch resolved to an exact commit;
- a bounded recursive tree;
- a bounded set of high-value UTF-8 text files.

It does not intentionally persist a complete repository clone or execute repository code. Evidence excerpts included in a report are bounded and passed through suspected-secret redaction. Static detection can miss sensitive material, so public repositories remain untrusted input.

## Data not intentionally collected

ForkWise does not require or intentionally collect in the anonymous beta:

- passwords or payment information;
- private repository contents;
- GitHub OAuth credentials from users;
- repository build outputs;
- runtime application data from the reviewed project;
- repository-controlled telemetry generated by executing the project, because the project is not executed.

An optional server-side GitHub token, when configured, is an operator secret. It must never be returned to clients, written to reports, or included in application logs.

## Retention

The intended anonymous hosted retention window is seven days. Expired job and report rows are removed through the service-role-only `purge_expired_analyses()` operation. Before hosted beta activation, the project must verify that cleanup is scheduled, monitored, and documented in the user interface.

Browser-downloaded JSON or Markdown reports are retained wherever the user stores them and are outside ForkWise's hosted retention controls.

## Direct database access

`analysis_jobs` and `analysis_reports` use PostgreSQL row-level security. No anonymous or authenticated browser policies are intentionally granted. Application access is through the server-side service role only.

## Logging and metrics

Allowed structured operational fields include:

- job ID;
- normalized repository key, not file content;
- status/progress stage;
- public error code;
- duration and bounded-count measurements;
- decision and evidence-coverage aggregate;
- analyzer and schema version.

Logs must not contain:

- repository file bodies or evidence excerpts;
- suspected secret values;
- service-role or GitHub tokens;
- raw authorization headers;
- complete reports;
- unredacted upstream error payloads.

## User controls planned before general availability

- clear disclosure of browser versus hosted processing;
- report expiration and anonymous-retention notice;
- authenticated report listing, deletion, and export;
- organization retention configuration where appropriate;
- abuse and acceptable-use controls;
- a contact and process for privacy or security requests.

## Known limitations

- Secret redaction is heuristic and cannot guarantee discovery of every credential format.
- Public source code may contain personal or sensitive information uploaded by repository maintainers.
- Static analysis cannot prove runtime data flow.
- The current anonymous beta has no authenticated user data-control portal.

## Approval gate

This draft must be reviewed and replaced or explicitly approved before ForkWise is promoted beyond a limited beta. Product copy must not claim regulatory compliance or guaranteed privacy based solely on this implementation.
